# AI 基础能力约定

## 1. 目标

AI 基础能力层的职责，是为所有 demo 提供一套稳定、可复用、可替换的底层轨道。

Land 中的 demo service 不应该再重复处理：

- provider 选择
- API key / base URL / model name 读取
- 模型档位选择
- session / message 基础结构
- 通用 AI 错误类型

这些能力应统一沉淀到 AI 基础层。

## 2. 分层约定

当前采用“纯 package + API 适配层”的折中方案：

```text
demo service
  -> apps/api/src/ai
  -> packages/ai-core
  -> provider SDK
```

职责划分：

- `packages/ai-core`
  - 纯 TypeScript 能力
  - provider 注册表（内置默认 baseUrl + modelNames）
  - 类型与校验
  - model factory
  - session manager
  - 通用 AI 错误类型
- `apps/api/src/ai`
  - 与 NestJS runtime 集成
  - 读取 `ConfigService`
  - 选择当前 provider
  - 创建 default / stable / creative / streaming model
  - 暴露共享 session manager
- `apps/api/src/demos/*`
  - 只关心 demo 输入校验
  - 只关心 prompt / chain / tools / output
  - 不自己拼 provider 配置

## 3. 模型创建规范

当前统一提供四个模型档位：

- `createDefaultModel()`
- `createStableModel()`
- `createCreativeModel()`
- `createStreamingModel()`

推荐用法：

- 稳定任务：
  使用 `createStableModel()`，例如周报、结构化输出、评估。
- 普通生成：
  使用 `createDefaultModel()`。
- 创意任务：
  使用 `createCreativeModel()`。
- 流式输出：
  使用 `createStreamingModel()`。

如果 demo 确实需要覆盖温度、maxTokens 等参数，可以在调用时传 override，但不要重新实现 provider 读取逻辑。

## 4. Provider 配置规范

### 当前支持的 LLM Provider

| Provider   | 内置 Base URL                                       | 内置模型列表（默认取第一个）           | 所需环境变量       |
| ---------- | --------------------------------------------------- | -------------------------------------- | ------------------ |
| `deepseek` | `https://api.deepseek.com`                          | `deepseek-v4-pro`, `deepseek-v4-flash` | `DEEPSEEK_API_KEY` |
| `glm`      | `https://open.bigmodel.cn/api/paas/v4`              | `glm-4-flash`, `glm-4-plus`            | `GLM_API_KEY`      |
| `qiniu`    | `https://api.qnaigc.com/v1`                         | `deepseek/deepseek-v3.2-exp-thinking`  | `QINIU_API_KEY`    |
| `qwen`     | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.6-plus`                         | `QWEN_API_KEY`     |

### 用户配置方式

用户只需在 `.env` 中配置：

```dotenv
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-xxx
```

`baseUrl` 和 `modelName` 由注册表内置，无需用户填写。
如需覆盖，可通过对应的 `*_BASE_URL` 和 `*_MODEL_NAME` 环境变量覆盖。

### 新增 Provider

新增 LLM provider 只需两步：

1. 在 `packages/ai-core/src/provider-config.ts` 的 `llmProviderRegistry` 中添加条目
2. 类型自动推导（`LlmProvider` 由 registry 的 key 推断）

用户只需在 `.env` 中配置对应的 API key 即可使用。

### 向量化 Provider（预留）

后续接入 RAG / embedding 时启用。当前注册表已预留 `qwen` 作为默认嵌入 provider：

```typescript
export const vectorProviderRegistry: Record<VectorProvider, VectorProviderEntry> = {
  qwen: {
    apiKeyEnvName: 'QWEN_API_KEY',
    defaultEmbeddingBaseUrl: 'https://dashscope.aliyuncs.com/compatible-mode/v1',
    defaultEmbeddingModelNames: ['text-embedding-v3'],
  },
}
```

## 5. Session 规范

当前 `SessionManager` 先使用内存 `Map`，对外暴露：

- `createSession()`
- `addMessage()`
- `getHistory()`
- `getRecentMessages()`
- `endSession()`
- `cleanupExpiredSessions()`

这层是后续多轮对话、Memory、Agent trace 的统一入口。后续替换 Redis / MongoDB / MySQL 时，应尽量保持方法语义稳定。

## 6. 错误规范

当前统一错误类型包括：

- `AiConfigurationError`
- `AiProviderUnsupportedError`
- `AiProviderRequestError`
- `AiOutputParseError`

要求：

- demo service 不手写 provider 缺失错误文案。
- API controller / filter 统一把这些错误转为用户可理解的响应。
- unknown error 不应泄露敏感细节或 stack 给前端。

## 7. Demo Service 禁止事项

demo service 中禁止：

- 自己判断 `AI_PROVIDER === 'deepseek' | 'qwen'`
- 自己读取 `DEEPSEEK_API_KEY` / `QWEN_API_KEY`
- 自己维护 provider 配置映射
- 自己实现 session 容器
- 把 AI 通用错误类型散落在业务层重复定义

如果某个 demo 需要新的 AI 基础能力，应优先扩展 `ai-core` 或 `apps/api/src/ai`，而不是临时在 demo 里单独实现。

## 8. 后续扩展方向

后续可继续向 AI 基础层扩展：

- embedding factory（已预留 `vectorProviderRegistry`）
- vector store factory
- run log / evaluation record
- token usage / cost record
- prompt version 管理
- Redis / MongoDB / MySQL 持久化 session
- RAG / Agent 的通用 trace 结构

原则不变：公共能力上收，demo 业务下沉。
