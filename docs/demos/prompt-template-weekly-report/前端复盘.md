# Prompt Template 周报生成 Demo 前端复盘

## 1. 页面设计与分层

这个 demo 的前端页面采用“左业务交互、右学习上下文”的布局。

左侧是主要任务流：

- 输入参数表单。
- 普通运行与流式运行按钮。
- 模型输出展示窗口。

右侧是学习辅助信息：

- 关键代码业务逻辑说明。
- 学习目标。
- 来源链接和已知限制。
- 原始源码对照。

这样分层的原因是：用户进入 demo 页面后，第一优先级是跑通一次 AI 生成；源码和解释应该随时可见，但不应该压过交互主流程。

## 2. 交互设计复盘

当前有两种输出模式：

1. **普通运行**
   等待后端返回完整文本。前端展示局部 Loading 面板，告诉用户模型正在生成。它适合结果需要完整阅读、结构稳定、不关心 token 过程的场景。

2. **流式运行**
   通过 SSE 逐步展示 token。前端不再展示普通 Loading，而是让内容本身成为反馈。它适合长文本、用户希望观察生成过程、或者模型首 token 延迟可接受但总生成时间较长的场景。

输出窗口限制在约 `540px`，避免周报内容把页面撑得过长。streaming 时每 3 秒自动滚动到底部，并在开始和结束时补一次贴底。这里没有选择每个 token 都滚动，因为那会干扰阅读，也可能造成滚动和渲染上的性能压力。

## 3. AI 输出展示方式选择

不同 AI 输出适合不同前端展示方式：

- **等待完整结果**
  适合短文本、结构化程度高、用户主要关心最终结果的场景。例如标题生成、摘要生成、分类结果。

- **SSE 流式输出**
  适合长文本生成、对话、报告、代码解释等场景。它能降低用户等待焦虑，也方便观察模型生成过程。

- **JSON 化输出**
  适合需要前端二次渲染的场景。例如结构化周报、表格、卡片、图表、流程步骤。模型返回 JSON 后，前端可以用稳定组件渲染，而不是直接展示一大段 Markdown。

- **自定义组件输出**
  适合复杂 demo，例如 RAG 引用来源、Agent 工具调用轨迹、多步骤任务进度。此时输出不只是文本，而是事件流和状态机。

对当前周报 demo 来说，Markdown 文本 + SSE 是合理的第一版。但如果要做得更产品化，下一步更适合让后端返回结构化 JSON，再由前端渲染 summary、指标表、风险列表和下周计划。

## 4. 可优化点

### 交互体验

- 增加“暂停自动滚动 / 跳到底部”按钮，避免用户阅读历史内容时被自动贴底打断。
- 增加“复制 Markdown”“下载周报”“重新生成”操作。
- 增加 prompt preview，让用户看到最终送入模型的 prompt。
- 增加运行耗时和 token 状态提示，例如“首 token 用时”“生成中”“已完成”。

### 输出渲染

- 引入 Markdown 渲染与代码高亮，让周报表格、标题和列表更易读。
- 支持 JSON schema 输出后用组件渲染，减少模型 Markdown 格式不稳定带来的 UI 波动。
- 给长文本输出增加目录、折叠区或分段锚点。

### 样式与布局

- 输出面板可以增加阅读模式，例如浅色纸张风格和深色终端风格切换。
- 移动端可以把右侧学习信息折叠成 tabs 或 accordion，避免页面过长。
- 原始源码对照可以增加“只看关键片段 / 查看完整源码”的切换。

### 安全

- 禁止前端接触任何 provider key，这点已经满足。
- 如果未来支持用户输入 Markdown 或 HTML，需要避免 `v-html` 直接渲染未清洗内容。
- 对复制、下载、外链跳转等操作增加明确来源提示。

### 性能

- streaming 输出较长时，后续可以做虚拟列表或分段渲染，避免一个超长 `pre` 节点持续变大。
- 自动滚动要继续节流，避免每个 token 都触发布局计算。
- 复杂 demo 的右侧源码面板可以按需加载，减少初始页面负担。

## 5. 评估方式

前端侧可以用这些指标判断优化是否有效：

- 点击普通运行后，局部 Loading 是否快速出现。
- streaming 长文本时，输出区域高度是否稳定，页面是否仍能自然滚动。
- 自动贴底是否能看到最新内容，同时不会频繁打断用户阅读。
- 移动端下输入、输出、源码区是否都可用。
- 同一份 AI 输出用 Markdown 文本、JSON 渲染、自定义组件渲染三种方式对比，观察可读性和稳定性。

## 6. 当前结论

当前前端实现适合 demo hub 的第一阶段：足够轻、足够清晰、可解释。

下一阶段前端更值得投入的是两个方向：一是抽通用 AI 输出组件，二是把“模型文本”升级为“可渲染的数据结构”。前者提升接入效率，后者提升展示质量。
