# 测试规范

## 1. 测试框架

统一使用 vitest + @vitest/coverage-v8。

## 2. 测试分层

| 层级     | 范围                                    | 运行位置                                | 覆盖率要求  |
| -------- | --------------------------------------- | --------------------------------------- | ----------- |
| 单元测试 | 纯函数、工具函数、schema 校验           | `packages/*`、`apps/*/src/**/*.test.ts` | lines ≥ 70% |
| 集成测试 | NestJS module、controller、service 组合 | `apps/api/src/**/*.test.ts`             | lines ≥ 60% |
| E2E      | 暂不要求                                | -                                       | -           |

## 3. 命名约定

### 文件名

- 测试文件按 DDD/feature 边界放在对应模块的 `__tests__` 目录
- 纯函数、schema、工具函数测试后缀 `.test.ts`
- module、controller、service 组合测试后缀 `.spec.ts`
- 示例：`src/content.ts` → `src/__tests__/content.test.ts`
- 示例：`src/demos/foo/foo.service.ts` → `src/demos/foo/__tests__/foo.service.spec.ts`

### 测试描述

使用 `describe` / `it` 嵌套，描述使用中文：

```typescript
describe('createChatModel', () => {
  it('接受合法的 openai 配置', () => {
    /* ... */
  })
  it('缺少 apiKey 时抛出 AiConfigurationError', () => {
    /* ... */
  })
})
```

### 测试结构

- `describe`：被测试的模块/函数/类名
- `it`：单个行为或边界情况，描述用中文
- 每个 `it` 只测一个行为

## 4. Mock 规范

- AI 模型调用必须 mock（不依赖真实 API）
- 使用 `vi.mock()` 在文件顶部统一 mock 外部依赖
- Mock 放在 `beforeEach` 中对每个测试重置状态

```typescript
import { describe, it, expect, beforeEach, vi } from 'vitest'

vi.mock('@langchain/openai', () => ({
  ChatOpenAI: vi.fn().mockImplementation(() => ({
    /* ... */
  })),
}))

beforeEach(() => {
  vi.clearAllMocks()
})
```

## 5. 测试覆盖要求

### 各 package 覆盖率阈值

| Package         | Lines    | Branches | Functions | Statements |
| --------------- | -------- | -------- | --------- | ---------- |
| `ai-core`       | ≥ 70%    | ≥ 60%    | ≥ 70%     | ≥ 70%      |
| `shared`        | ≥ 80%    | ≥ 70%    | ≥ 80%     | ≥ 80%      |
| `demo-registry` | ≥ 70%    | ≥ 60%    | ≥ 70%     | ≥ 70%      |
| `apps/api`      | ≥ 60%    | ≥ 50%    | ≥ 60%     | ≥ 60%      |
| `apps/web`      | 暂不要求 | -        | -         | -          |

阈值配置在各 package 的 `vitest.config.ts` 中。

### 必须测试的场景

- **正常路径**：合法输入得到预期输出
- **边界值**：空字符串、null、undefined、0、空数组
- **错误路径**：非法输入抛出正确异常
- **配置缺失**：AI provider 配置不完整时给出明确错误

## 6. 运行命令

```bash
# 全量测试
pnpm test

# 单个 package 测试
pnpm test --filter @ai-journey-land/ai-core

# 覆盖率报告
pnpm --filter @ai-journey-land/ai-core exec vitest run --coverage

# 监听模式（开发时）
pnpm --filter @ai-journey-land/ai-core exec vitest
```

## 7. CI 要求（计划中）

- `pnpm typecheck` 必须通过
- `pnpm test` 必须通过（满足覆盖率阈值）
- `pnpm lint` 必须通过
- 后续接入 GitHub Actions 自动执行

## 8. 测试先行原则

- 新功能开发：先写测试描述预期行为，再写实现
- Bug 修复：先写测试复现 bug，再修代码
- 重构：先确保已有测试通过，再改代码，重构过程中不降覆盖率

## 9. 测试质量底线

- 不写只断言“函数存在”“模块能 import”这类无业务意义的模板测试
- 不用硬编码方式迁就当前实现，测试要面向行为和契约
- 测试数据要能表达业务意图，必要时通过 factory/helper 生成
- 与外部服务相关的测试必须 mock provider、网络请求和模型输出
- 每个 issue 完成前至少运行 `pnpm typecheck && pnpm test`
